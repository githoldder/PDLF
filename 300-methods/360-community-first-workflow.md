# Community First 工作流

> **Community First 不是"先问别人"，而是"先借别人的认知"来校准自己的判断。**
>
> 关键问题：你遇到的问题，别人大概率也遇到过。区别在于，你能否用正确的方式找到他们的经验。

---

## 核心原则

### 为什么社区搜索比直接问 AI 更有效？

| 维度 | AI 生成 | 社区经验 |
|------|---------|---------|
| 时效性 | 训练数据有截止日期 | 实时更新，反映最新实践 |
| 场景匹配 | 通用回答 | 针对具体场景的经验 |
| 验证度 | 无法验证 | 多人投票、评论验证 |
| 边界认知 | 不会主动说"这不行" | 失败案例同样珍贵 |
| 隐性知识 | 无法表达 | 吐槽、评论中的潜规则 |

**结论**：AI 擅长"生成方案"，社区擅长"验证方案"。两者结合，效率最高。

---

## 工作流：三个动作

```
动作 1: 关键词排列组合
    ↓
动作 2: 确定高质量信息源
    ↓
动作 3: 检索整合 + 归档映射
    ↓
输出: 带节点映射的参考文献列表
```

---

## 动作 1：关键词排列组合

### 为什么需要排列组合？

同一个问题，用不同的关键词搜索，结果差异巨大。

**示例**：API 响应变慢

| 关键词组合 | 搜索结果侧重 | 适用阶段 |
|-----------|-------------|---------|
| `MySQL DATE() index not used` | 具体技术原因 | Diagnose |
| `MySQL slow query optimization` | 通用优化方法 | Transform |
| `MySQL function on indexed column performance` | 深层原理 | Diagnose |
| `ORM generate DATE query index失效` | 框架层问题 | Diagnose |
| `MySQL EXPLAIN full table scan` | 诊断方法 | Diagnose |
| `database query P99 latency spike` | 监控/度量 | Discover |

### 关键词生成策略

#### 维度拆解法

将问题拆成多个维度，分别组合：

```
技术栈    +   现象       +   上下文
MySQL       索引失效      生产环境
PostgreSQL  查询慢       高并发
Redis       延迟飙升      大数据量
```

#### 同义词扩展法

```
慢查询 → 查询慢 / 查询耗时 / 查询性能 / 查询优化 / 查询延迟
索引失效 → 索引未使用 / 索引不生效 / 全表扫描 / 不走索引
```

#### 场景限定法

```
通用: "MySQL 索引失效"
限定: "MySQL DATE() 函数 索引失效 解决方案"
更限定: "MySQL DATE() 索引失效 Django ORM 生产环境"
```

### 关键词优先级

| 优先级 | 关键词特征 | 搜索目的 |
|--------|-----------|---------|
| P0 | 精确错误信息 / 错误码 | 找到完全匹配的问题 |
| P1 | 技术栈 + 现象 | 找到相似场景的经验 |
| P2 | 现象 + 解决方案类型 | 找到通用方法 |
| P3 | 通用概念 | 补充背景知识 |

## 动作 2：确定高质量信息源

### 信息源质量评估矩阵

| 信息源 | 专业度 | 活跃度 | 时效性 | 可验证性 | 推荐指数 |
|--------|--------|--------|--------|---------|---------|
| **Stack Overflow** | 高 | 极高 | 实时 | 投票+评论 | ⭐⭐⭐⭐⭐ |
| **GitHub Issues** | 高 | 高 | 实时 | 代码+复现 | ⭐⭐⭐⭐⭐ |
| **官方文档** | 极高 | 中 | 定期 | 权威 | ⭐⭐⭐⭐⭐ |
| **技术博客** | 中-高 | 中 | 差异大 | 依赖作者 | ⭐⭐⭐⭐ |
| **Reddit / 知乎** | 中 | 高 | 实时 | 社区验证 | ⭐⭐⭐ |
| **微信公众号/掘金** | 中 | 高 | 实时 | 依赖作者 | ⭐⭐⭐ |
| **百度知道/简单问答** | 低 | 高 | 差异大 | 不可验证 | ⭐ |

### 分技术栈的推荐信息源

| 技术领域 | 首选 | 次选 | 备选 |
|---------|------|------|------|
| **通用编程** | Stack Overflow | GitHub Issues | Reddit r/programming |
| **前端** | Stack Overflow | GitHub Issues + 掘金 | CSS-Tricks / MDN |
| **后端 / 数据库** | Stack Overflow | GitHub Issues + 官方文档 | DBA Stack Exchange |
| **DevOps / 云** | Stack Overflow | GitHub Issues + 官方文档 | Server Fault |
| **AI / ML** | Stack Overflow | GitHub Issues + Papers | Reddit r/MachineLearning |
| **移动开发** | Stack Overflow | GitHub Issues | 官方开发者论坛 |
| **鸿蒙/Flutter** | 官方开发者论坛 | GitHub Issues | 掘金 / CSDN |

### 信息源选择策略

```
Step 1: 先搜 Stack Overflow（专业度高，投票机制过滤噪音）
Step 2: 再搜 GitHub Issues（找到真实代码和复现步骤）
Step 3: 查阅官方文档（验证权威信息）
Step 4: 补充技术博客（获取最新实践和隐性知识）
Step 5: 如果中文场景强，补充掘金/知乎（获取本土化经验）
```

## 动作 3：检索整合 + 归档映射

### 检索策略

#### 第一轮：精确搜索（P0 关键词）

```
目标：找到完全匹配的问题
方法：用错误信息、错误码、精确技术术语搜索
预期：1-3 条高度相关的结果
```

#### 第二轮：相似搜索（P1 关键词）

```
目标：找到相似场景的经验
方法：用技术栈 + 现象组合搜索
预期：3-5 条相关结果，验证第一轮结论
```

#### 第三轮：方法搜索（P2 关键词）

```
目标：找到通用解决方法
方法：用现象 + 解决方案类型搜索
预期：补充 Transform 阶段的方案选择
```

#### 第四轮：背景搜索（P3 关键词）

```
目标：补充背景知识
方法：用通用概念搜索
预期：理解深层原理，辅助 Diagnose
```

### 信息整合模板

每条检索结果需要提取：

```markdown
## 检索结果 [序号]

- **来源**: [Stack Overflow / GitHub Issues / 官方文档 / 博客]
- **URL**: [链接]
- **标题**: [原文标题]
- **相关性**: [高 / 中 / 低]
- **验证度**: [高赞回答 / 官方回复 / 多人确认 / 单一来源]
- **关键结论**: [一句话总结]
- **适用阶段**: [Discover / Triage / Diagnose / Transform / Solve / Verify]
- **映射节点**: [Problem Tree 或 Risk Tree 的节点编号]
- **是否解决当前问题**: [是 / 否 / 部分]
```

### 与问题树/风险树的映射

这是最关键的部分。**每条参考文献必须与问题树或风险树的具体节点一一对应**。

#### 映射规则

```
Problem Tree 节点          →    参考文献编号
[表象] P99 3200ms          →    REF-001, REF-002
[现象] 查询耗时增加         →    REF-003
[直接原因] 全表扫描         →    REF-004, REF-005
[结构原因] 索引失效         →    REF-006
[根因] DATE(created_at)    →    REF-007, REF-008
[因果节点] 测试数据量不足    →    REF-009
```

#### 为什么需要映射？

1. **验证每个节点的可靠性**：每个结论都有出处
2. **追溯假设的来源**：如果假设被推翻，知道从哪里开始的
3. **Agent 自检**：可以检查"这个结论是基于社区经验还是猜测"
4. **知识复用**：下次遇到相似节点，直接调用已有参考文献

## 参考文献归档规范

### 文件位置

```
/problem-tree/
├── problem.md
├── risk.md
└── references/
    ├── 001-stackoverflow-mysql-date-index.md
    ├── 002-github-orm-query-issue.md
    └── 003-official-mysql-docs-explain.md
```

### 文件命名规范

```
{NNN}-{source}-{keywords}.md
```

| 段 | 含义 | 示例 |
|---|------|------|
| `NNN` | 序号，与 problem.md 中的 REF-NNN 对应 | 001 |
| `source` | 来源缩写 | stackoverflow / github / docs / blog |
| `keywords` | 核心关键词 | mysql-date-index |

### 文件内容模板

```markdown
# REF-001: MySQL DATE() function causes index skip

## 来源信息
- **平台**: Stack Overflow
- **URL**: https://stackoverflow.com/questions/...
- **提问时间**: 2023-05-12
- **回答时间**: 2023-05-13
- **投票数**: 284 upvotes
- **被采纳**: 是

## 问题摘要
提问者遇到 MySQL 中 `WHERE DATE(created_at) = '2023-05-01'` 不走索引的问题。

## 核心结论
在索引列上使用函数会导致索引失效，应改写为范围查询。

## 关键代码
```sql
-- 失效
WHERE DATE(created_at) = '2023-05-01'

-- 有效
WHERE created_at BETWEEN '2023-05-01 00:00:00' AND '2023-05-01 23:59:59'
```

## 验证信息
- [x] 有多人确认（评论区 15+ 条验证）
- [x] 有官方文档支持（MySQL 8.0 文档索引章节）
- [ ] 有性能测试数据

## 映射节点
- **Problem Tree**: [根因] DATE(created_at) 导致索引失效
- **Risk Tree**: [失效模式] 函数包裹索引列

## 适用阶段
- **主要**: Diagnose（确认根因）
- **次要**: Transform（提供解决方案）

## 可信度评估
- **专业度**: 高（回答者有 MySQL 专家标签）
- **时效性**: 中（2023 年，MySQL 8.0）
- **可复现**: 高（提供了 EXPLAIN 验证方法）

## 备注
- 适用于 MySQL 5.7+ 和 8.0
- PostgreSQL 行为相同
- SQL Server 有类似问题
```

## Agent 执行模板

当 Agent 执行 Community First 时，按以下流程：

```
【阶段】Community First
【动作 1：关键词生成】
  基于当前问题描述，生成以下关键词组合：
  - P0（精确）: [关键词]
  - P1（相似）: [关键词]
  - P2（方法）: [关键词]
  - P3（背景）: [关键词]

【动作 2：信息源选择】
  根据技术栈，选择以下信息源：
  - 首选: [信息源]
  - 次选: [信息源]
  - 备选: [信息源]

【动作 3：检索执行】
  执行 4 轮检索，记录结果：
  - 第一轮（精确）: [N] 条结果
  - 第二轮（相似）: [N] 条结果
  - 第三轮（方法）: [N] 条结果
  - 第四轮（背景）: [N] 条结果

【动作 4：整合映射】
  将参考文献与问题树节点映射：
  - [节点] → REF-[NNN]
  - [节点] → REF-[NNN]

【输出】
  - 生成 references/ 目录下的文件
  - 在 problem.md 中更新参考文献链接
  - 提供"关键结论摘要"
```

## 常见陷阱

| 陷阱 | 表现 | 修正 |
|------|------|------|
| **复制粘贴答案** | 直接照搬 Stack Overflow 代码 | 必须验证是否匹配当前场景 |
| **忽略时间戳** | 引用 5 年前的解决方案 | 检查技术栈版本是否兼容 |
| **只看高赞** | 忽略评论区的重要补充 | 阅读前 3 条评论 |
| **不验证来源** | 引用不知名博客的猜测 | 优先官方文档和验证过的回答 |
| **遗漏失败案例** | 只收集"成功解决"的经验 | 同样收集"尝试失败"的经验 |
| **不与节点映射** | 参考文献成了孤立的链接列表 | 每条引用必须关联到具体节点 |

---

## 一句话总结

> **Community First = 用正确的关键词 × 在正确的平台 × 找到正确的经验 × 映射到正确的节点。**
>
> 不是搜索技巧，是认知对齐。
