# Verify / Challenge 检查清单

> **解决问题 ≠ 问题已经被证明解决。**

---

## 五个验证维度

### 1. 验证：我们解决了吗？

- [ ] 原始症状是否消失？
- [ ] 验收标准是否全部通过？
- [ ] 是否有数据/日志/监控证明？

### 2. 挑战：如果我们错了，会怎么错？

- [ ] 根因假设是否经过证伪？
- [ ] 是否存在其他可能的根因？
- [ ] 解决方案是否只处理了表象？

### 3. 回归：有没有破坏原来正常的东西？

- [ ] 相关功能是否经过回归测试？
- [ ] 性能指标是否有退化？
- [ ] 用户流程是否受影响？

### 4. 边界：极端情况下还成立吗？

- [ ] 数据量增长 10 倍是否仍然有效？
- [ ] 并发量增加 10 倍是否仍然有效？
- [ ] 异常输入是否被正确处理？

### 5. 风险：有没有尚未暴露的问题？

- [ ] 解决方案是否引入了新的风险？
- [ ] 是否存在类似的潜在问题？
- [ ] 是否需要增加监控/告警？

---

## 攻击策略

| 攻击方式 | 问题 | 示例 |
|---------|------|------|
| **数据边界** | 如果数据量/并发量翻倍？ | "查询优化后，100万数据OK，1000万呢？" |
| **时序边界** | 如果执行顺序改变？ | "缓存失效和写入的竞态条件？" |
| **输入边界** | 如果输入异常/恶意？ | "SQL 注入、XSS、特殊字符？" |
| **依赖边界** | 如果依赖服务故障？ | "数据库降级时，服务行为？" |
| **配置边界** | 如果配置被误改？ | "超时阈值从 5s 改为 500ms？" |
