# FMEA 指南 (Failure Mode and Effects Analysis)

> **在问题真正发生之前，构建一个潜在问题树。**

---

## 评分标准

### 严重度 (Severity, S) — 发生后有多糟？

| 分数 | 含义 |
|------|------|
| 1-3 | 轻微不便，有 workaround |
| 4-6 | 功能降级，用户抱怨 |
| 7-8 | 核心功能丧失，数据风险 |
| 9-10 | 灾难性：安全、法律、系统完全崩溃 |

### 发生度 (Probability, P) — 有多可能发生？

| 分数 | 含义 |
|------|------|
| 1-3 | 罕见 / 仅理论上可能 |
| 4-6 | 偶尔 / 类似系统发生过 |
| 7-8 | 频繁 / 本系统曾发生 |
| 9-10 | 几乎必然 / 正在发生 |

### 探测度 (Unknown, U) — 我们有多不了解？

| 分数 | 含义 |
|------|------|
| 1-3 | 充分理解，已测试，已文档化 |
| 4-6 | 部分不确定，测试有限 |
| 7-8 | 高度不确定，全新领域 |
| 9-10 | 完全未知，无先例 |

---

## 风险优先级数 (RPN)

```
RPN = S × P × U
```

| RPN 范围 | 行动 |
|----------|------|
| 1-50 | 接受，持续监控 |
| 51-150 | 成本允许时缓解 |
| 151-300 | 发布前必须缓解 |
| 301-1000 | 立即停止，修复后再继续 |

---

## 示例: API 限流场景

| 失效模式 | S | P | U | RPN | 缓解措施 |
|---------|---|---|---|-----|---------|
| 突发流量压垮数据库 | 9 | 6 | 4 | **216** | 加熔断器 + 消息队列 |
| 限流阈值过于激进 | 5 | 7 | 3 | 105 | 灰度渐进调整 |
| 限流被伪造请求绕过 | 8 | 3 | 7 | **168** | Token 认证 + 审计日志 |

---

## 与 Risk Tree 的整合

Risk Tree 的 Triage 阶段直接使用 FMEA 三维度评分：

```markdown
## Triage
- [ ] severity: 8
- [ ] probability: 6
- [ ] unknown: 4
- [ ] risk_score: 192
```

Phase 4 (TRANSFORM) 对应 FMEA 的三种缓解策略：
- **Prevent** — 使其不可能发生
- **Detect** — 尽早发现
- **Recover** — 最小化影响范围
