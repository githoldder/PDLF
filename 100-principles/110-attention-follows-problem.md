# 核心原则：注意力追随问题

> **人的注意力不应该平均分配给每一个 Task，而应该跟随问题、风险和关键判断节点移动。**

---

## 一句话

**Attention Follows the Problem.**

不是 Every Task。

---

## 为什么是这个原则？

### 反直觉的事实

工程师最容易犯的错误，不是技术能力不足，而是**注意力分配错误**。

- 在不该投入的地方投入了 80% 的时间
- 在真正关键的地方只投入了 20% 的注意力
- 被任务的紧急性绑架，忽略了问题的重要性

### 两个空间

```
┌──────────────────┐      ┌──────────────────┐
│   Problem Space  │      │    Risk Space    │
│  (已知问题空间)   │  +   │  (潜在问题空间)   │
│                  │      │                  │
│  What happened?  │      │  What if?        │
│  Why?            │      │  What else?      │
│  How to solve?   │      │  How might fail? │
└──────────────────┘      └──────────────────┘
```

**传统做法**：只关注 Problem Space，解决完就结束。

**正确做法**：同时在两个空间中分配注意力，解决问题的过程中不断扫描风险空间。

---

## 注意力分配的三条规则

### 规则 1：模糊处投入最多

问题越模糊、越不确定，投入的注意力应该越多。

```
Discover ───────────────────────────────────────→ Learn
   ↑                                                ↑
   └─ 注意力投入逐渐降低 ──────────────────────────┘

Diagnose: 最高注意力（找到真正的问题）
Transform: 高注意力（设计最优路径）
Solve:     低注意力（交给工具执行）
```

### 规则 2：决策点比执行点重要

人不是在每个 Task 上监督 Agent，而是在**关键决策节点**上进行高价值判断。

关键决策节点：
- Triage（是否值得处理？）
- Transform（怎么问更好？）
- Verify（真的解决了吗？）

### 规则 3：风险空间需要持续扫描

不是在问题解决后才考虑风险，而是在**每个阶段**都问：

> "什么可能让这一步失败？"

---

## 与 AI 的关系

```
人类:  控制问题空间 + 风险空间 + 决策点
AI:    扩大搜索空间 + 执行空间 + 验证空间
```

**不是替代，是重新分配。**

AI 越强，执行越便宜；人类的价值越集中在定义问题、转化问题、预见风险。

---

## 一句话总结

> **PDLF 的目的：把注意力重新还给人类。**
