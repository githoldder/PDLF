# 核心转向

PDLF 建立在三个认知转向之上。理解这三个转向，就理解了这个框架的底层逻辑。

---

## 转向 1：从"解决问题"到"管理问题"

**从**: "我有一个问题，我要解决它"

**到**: "问题有自己的生命周期，我在每个阶段做出正确的决策"

### 为什么重要？

因为**决策对了，执行自然高效；决策错了，执行越快浪费越大**。

初级工程师花 80% 时间在执行，20% 在思考。

高级工程师花 80% 时间在思考（定义、转化、验证），20% 在执行。

---

## 转向 2：从"单点修复"到"系统预防"

**从**: "这个 Bug 修完了，可以关闭了"

**到**: "这个 Bug 给未来提供了什么新知识？"

### 为什么重要？

因为**问题的价值不在于它被解决，而在于它教会了系统什么**。

每一次问题处理，都应该增加系统"提前发现"的能力。

```
Bug
 ↓
Root Cause
 ↓
Solution
 ↓
Detection Method  ← 新的发现能力
 ↓
Prevention Rule   ← 新的免疫能力
 ↓
Test Case         ← 新的验证能力
 ↓
Risk Pattern      ← 新的识别能力
```

---

## 转向 3：从"人的执行"到"人的决策"

**从**: "人类做所有事，AI 辅助"

**到**: "人类做关键决策，AI 扩大执行和搜索空间"

### 为什么重要？

因为**AI 的瓶颈不在执行能力，而在问题定义的质量**。

同一个 AI，被给予不同的问题表示，产出的质量天差地别。

```
差的问题表示        →    好的问题表示
"帮我优化代码"      →    "将这个 O(n²) 查询改写为 O(log n)"
"系统有点慢"        →    "P99 > 200ms 的接口识别与根因分析"
"有个 Bug"          →    "在 X 条件下 Y 函数返回 Z 而非 W"
```

人类的价值在于：
- **定义**问题（Discover / Diagnose）
- **转化**问题（Transform）
- **预见**风险（Verify / Learn）

AI 的价值在于：
- **搜索**解空间（Solve）
- **攻击**解空间（Verify 中的边界扫描）
- **沉淀**知识（Learn 中的模式提取）

---

## 三个转向的关系

```
转向 1: 管理问题（ WHAT ）
    ↓
转向 2: 系统预防（ WHY ）
    ↓
转向 3: 人机协作（ HOW ）
```

**管理问题**是目的，**系统预防**是结果，**人机协作**是手段。

---

## 检验你是否理解

如果你能回答以下三个问题，说明你已经掌握了这个框架的核心：

1. **为什么 Triage 要做两次？**
   → 因为定位后才知道真正有多重要。

2. **为什么 Risk Tree 要贯穿全程？**
   → 因为每个阶段都可能失败，不是只有解决后才考虑风险。

3. **为什么 AI 应该停在 Transform？**
   → 因为问题的表示质量决定了 AI 的产出质量，人类必须在转化阶段把关。
