# 一个原则 · 两颗树

> 整个 PDLF 可以浓缩为一个原则、两颗树。记住这 3 个概念，就掌握了框架的核心。

---

## 一个原则

**Attention Follows the Problem.**

注意力跟着问题走，不是跟着 Task 走。

### 两个空间

```
┌──────────────────┐      ┌──────────────────┐
│   Problem Space  │      │    Risk Space    │
│  (已知问题空间)   │  +   │  (潜在问题空间)   │
│                  │      │                  │
│  What happened?  │      │  What if?        │
│  Why?            │      │  What else?      │
│  How to solve?   │      │  How might fail? │
└──────────────────┘      └──────────────────┘
```

**传统做法**：只关注 Problem Space，解决完就结束。

**正确做法**：同时在两个空间中分配注意力，解决问题的过程中不断扫描风险空间。

### 注意力分配规则

| 阶段 | 注意力 | 原因 |
|------|--------|------|
| Diagnose | **最高** | 问题最模糊，最需要投入 |
| Transform | 高 | 设计最优路径 |
| Verify | 中高 | 确保真的解决，攻击盲区 |
| Solve | 低 | 已清晰，交给 AI 执行 |

**核心规则**：问题越模糊、越不确定，投入的注意力应该越多。

---

## 两颗树

### Problem Tree — 问题发生了

**目的**：提高解决问题的效率

**核心问题**：真正的问题是什么？

**构建方法**：
- **纵向**：5Why — 层层追问直到因果节点
- **横向**：问题转化 — 改变表达方式、边界或约束

```
表象
  ↓
现象
  ↓
直接原因
  ↓
结构原因
  ↓
根本问题（因果节点）
```

**停止信号**：找到可以永久解决问题的因果节点。

### Risk Tree — 问题还没发生

**目的**：避免问题发生的可能

**核心问题**：还可能在哪里失败？

**构建方法**：
- **FMEA**：Severity × Probability × Unknown = RPN
- **边界测试**：极端情况还成立吗？
- **对抗思维**：如果我们错了，会怎么错？

```
已知风险
  ↓
潜在失效模式
  ↓
影响分析
  ↓
缓解策略（Prevent / Detect / Recover）
```

**关键特性**：Risk Tree 不是末端归档，而是**贯穿全程**。每个阶段都问："什么可能让这一步失败？"

---

## 两棵树的关系

```
        Problem Tree
       "真正要解决什么？"
              ↓
         Solve it
              ↓
         Risk Tree
       "还可能在哪里失败？"
              ↓
         Prevent it
              ↓
         回到 Problem Tree（下一次）
```

- **Problem Tree** 解决的是**现在**的问题
- **Risk Tree** 解决的是**未来**的问题
- **Risk Tree 是最关键的树**，因为它连接了现在和未来

---

## 与 AI 的关系

```
人类:  Problem Tree + Risk Tree + 关键决策节点
AI:    扩大搜索空间 + 执行空间 + 验证空间
```

**人类的价值**：
- 定义问题（Problem Tree）
- 转化问题（Transform）
- 预见风险（Risk Tree）

**AI 的价值**：
- 搜索解空间（Solve）
- 攻击解空间（Verify 中的边界扫描）
- 沉淀知识（Learn 中的模式提取）
